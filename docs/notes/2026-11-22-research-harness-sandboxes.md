## Codex CLI
1. OS sandbox, default on. https://learn.chatgpt.com/docs/agent-approvals-security : "Locally, Codex uses an OS-enforced sandbox that limits what it can touch." macOS Seatbelt, Linux bwrap + seccomp, Windows (per page). https://learn.chatgpt.com/docs/sandboxing : "The default permissions mode applies sandboxing automatically." Default mode workspace-write; network off.
2. Writable roots: sandboxing page points to `sandbox_workspace_write.writable_roots` (Configuration reference; that page 404'd at /docs/config-reference). Built-in protection: "`<writable_root>/.git` is protected as read-only whether it appears as a directory or file." and "`<writable_root>/.codex` is protected as read-only when it exists as a directory." Per-subdirectory control via permission profiles, https://learn.chatgpt.com/docs/permissions : "Filesystem entries use `read`, `write`, or `deny`:" ; "Nested subpaths must stay inside their workspace root." ; more specific entries override broader, `deny` beats `write` beats `read`. => a protected dir (deny/read) and "write only one subdir" (workspace read + subpath write) appear expressible; not verified by running.
3. Hooks, https://learn.chatgpt.com/docs/hooks : PreToolUse, UserPromptSubmit, Stop listed; "`hooks.json` from system, user, and trusted project scopes" or inline `[hooks]` in config.toml; PreToolUse deny: "To deny a supported tool call, return this hook-specific shape:"; shell matched as `Bash`. Stop block "doesn't reject the turn" (it continues).
4. MCP, https://learn.chatgpt.com/docs/extend/mcp?surface=cli : "Codex stores MCP configuration in `config.toml` alongside other Codex configuration settings." (`codex mcp add`; project `.codex/config.toml` for trusted projects).
5. Auth, https://learn.chatgpt.com/docs/auth : "Sign in with ChatGPT for subscription access"; "In these situations, prefer device code authentication (beta)."; cache "~/.codex/auth.json". Same page: "Use API key authentication for programmatic Codex CLI workflows, such as CI/CD jobs." (codex exec not mentioned on that page; non-interactive use of subscription creds = reuse cached auth.json, unverified here.)

## Gemini CLI
1. https://geminicli.com/docs/cli/sandbox/ : macOS Seatbelt "Lightweight, built-in sandboxing using `sandbox-exec`."; Docker/Podman "Cross-platform sandboxing with complete process isolation"; also gVisor, LXC, Windows native. Default NOT stated; implies opt-in ("Enable sandboxing using one of the following methods"; flag `-s`, env `GEMINI_SANDBOX`, settings.json); raw github doc has same wording.
2. Seatbelt default profile `permissive-open`: "denies operations by default; confines writes to the project directory". Extra mounts: `SANDBOX_MOUNTS` "a comma-separated list of mount definitions in the format `from:to:opts`" (default read-only). Profile via SEATBELT_PROFILE. Read-only subdir inside workspace / write-only-one-subdir: not documented in fetched text (unverified).
3. Hooks, https://geminicli.com/docs/hooks/ : BeforeAgent ("After user submits prompt, before planning"), AfterAgent, BeforeTool ("Block Tool / Rewrite"), AfterTool, etc. "Hooks are configured in `settings.json`." Exit code 2: "The target action (tool, turn, or stop) is aborted." Layers: project, user, system, extensions.
4. MCP, https://geminicli.com/docs/tools/mcp-server/ : "This document provides a guide to configuring and using Model Context Protocol (MCP) servers with Gemini CLI."
5. Auth, https://geminicli.com/docs/get-started/authentication/ : "Most individual Google accounts (free and paid) don’t require a Google Cloud project for authentication."; "Headless mode will use your existing authentication method, if an existing authentication credential is cached." ## OpenCode
1. No OS sandbox. https://opencode.ai/docs/permissions/ : "`shell` runs with the host user's filesystem, process, and network authority" (page recommends narrow allowlists). Permissions are pattern rules in opencode.jsonc; "The default policy allows `external_directory`".
2. Only permission rules (edit path patterns / shell command patterns), not kernel enforcement; shell can bypass edit rules. OS-level subdir read-only: none.
3. Plugins, https://opencode.ai/docs/plugins/ : "Create plugins that add tools, hooks, integrations, commands, agents, and other behavior." Auto-loaded from `.opencode/plugins/`. https://opencode.ai/docs/build/plugins/server : tool hook "Inspect or replace tool input before execution."; "Prompt hooks transform input and do not expose a typed rejection API."; permission hook can set effect to `deny`. (Whether a tool hook can block by throwing: not stated.)
4. MCP, https://opencode.ai/docs/mcp-servers/ : "connects to Model Context Protocol servers and exposes capabilities such as tools, prompts, resources, and instructions."
5. Auth, https://opencode.ai/docs/providers/ : "Use a ChatGPT Plus or Pro plan instead of an OpenAI API key."; Copilot "supports device OAuth". Claude Pro/Max not covered; non-interactive auth not documented there.

## Grok CLI (exists: xAI "Grok Build", command `grok`; repo https://github.com/xai-org/grok-build ; docs https://docs.x.ai/build/overview). Not the community superagent-ai/grok-cli.
1. .../xai-grok-pager/docs/user-guide/18-sandbox.md (under https://github.com/xai-org/grok-build/blob/main/crates/codegen/): "OS-level kernel primitives (Landlock on Linux, Seatbelt on macOS)"; "Sandbox mode is off by default."; "child processes inherit FS restrictions automatically." Flag `--sandbox <PROFILE>`. Network blocking only on Linux.
2. Profiles in `~/.grok/sandbox.toml` or `.grok/sandbox.toml` (per-project); fields `read_write` ("Additional read-write paths"), `read_only` ("Paths the agent can read but NOT write/delete"), `deny` (blocks read+write); literal dirs, not globs. Example `[profiles.project] extends = "workspace"`. Not confirmed by doc: read_only carve-out inside a writable parent; "only one subdir writable" via extends read-only + one read_write is inference, unverified.
3. Hooks, 10-hooks.md : "A hook is a shell command or HTTP endpoint that Grok calls when a specific lifecycle event occurs."; PreToolUse, UserPromptSubmit, Stop; "Only an explicit `deny` decision returned by the hook blocks a tool call." Hook failures FAIL OPEN. Project hooks `.grok/hooks/` need folder trust; also scans Claude/Cursor settings.
4. MCP, 07-mcp-servers.md : "MCP servers are configured in `~/.grok/config.toml` under `[mcp_servers.<name>]` sections."
5. Auth, 02-authentication.md : "On first launch, Grok opens your browser to authenticate with grok.com."; "For CI/CD, automation, or environments without browser access, use an API key from console.x.ai." (`XAI_API_KEY`). `grok login --device-auth` for headless (https://docs.x.ai/build/cli/reference). SuperGrok subscription not named on the page.
