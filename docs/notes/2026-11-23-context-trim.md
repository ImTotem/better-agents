# 모델 컨텍스트에 들어가는 글 줄이기 (2026-11-23)

사용자 요청: "토큰 낭비 안되게 내용좀 정리해라. 단, 내용을 정리할때 기능에 영향이 가서는 안된다."
반복, 군더더기, 같은 파일 안의 중복만 덜어 냈다. 규칙, 조건, 명령, 도구 이름, `GA` 줄, 종료 코드, 경로, JSON 필드는 모두 남겼다.
코드 동작은 바꾸지 않았다. `server.sh`는 설명 문자열만, `prompt.md`는 출력 약속(JSON 모양, 필드, 값) 밖의 글만 고쳤다.

## 단계별 파일로 나누기 (두 번째 커밋)

`SKILL.md`의 2~6절(단계별 할 일)을 `skills/arch/phases/<단계>.md`로 옮겼다. 내용은 그대로이고, 제목의 절 번호를 빼고 다른 절을 가리키는 말만 고쳤다(예: "1절 절차" → "SKILL.md 1절의 검증과 승인 절차", "3절을 따른다" → "`phases/iterating.md`를 따른다").
`SKILL.md`에는 0절, 1절, 새 2절(단계 → 파일 → 승인 줄 표), 3절(옛 7절 명령 표)이 남았다.

언제 무엇이 들어가는가:
- `/arch`를 부르면 `SKILL.md`만 들어간다(10136자).
- 단계를 시작할 때와 압축 뒤에는 `ga status`로 단계를 확인하고, `SKILL.md` 0절과 1절, 지금 단계의 `phases/<단계>.md` 하나만 다시 읽는다(6731자 + 458~2874자).
- 다른 단계의 파일은 그 단계가 되기 전에는 읽지 않는다.

`tests/test_skills.sh`는 도구 이름, `ga` 명령, `GA` 줄 검사를 `skills/arch` 아래 모든 `.md`로 넓혔다. 게이트가 받는 단계(`gates.sh`의 목록)마다 `phases/` 파일이 있고 `SKILL.md`에 나오는지 보는 테스트도 더했다.

## 다른 파일에서 바꾼 것

- `guide.md`: 3절의 `## 지금 상황` 규칙(3문장, 결과 먼저)과 `## 정해 주실 것` 규칙(추천 먼저, 이유, 선택지마다 결과)은 2절 양식 틀에 그대로 있어서 3절에서 뺐다. 사용자 인용(2026-11-22)은 뺐고 이유는 한 문단으로 줄였다.
- MCP 설명: 각 도구 설명 끝의 CLI 모양(`(ga add KIND, …)`)을 뺐다. 서버 안내문이 "같은 이름의 ga 하위 명령을 실행한다"고 말한다. `root` 인자의 "없으면 CLAUDE_PROJECT_DIR"도 안내문에만 남겼다.
- `prompt.md`: 검증 모델이 볼 수 없는 "항목 3.5절"(설계 명세의 탐색 범위 절)을 "탐색 기록의 `conversation`(현재 대화) 칸"으로 바꿨다.
- `grounding.md`와 스킬 본문은 같은 글로 함께 줄였다(테스트가 둘이 같은지 본다).
