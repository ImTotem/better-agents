# AI 진행자가 사용자 대신 내린 결정 모음 (2026-11-23)

플러그인(근거 기반 아키텍처 설계 도구, `grounded-arch`)을 만드는 동안 AI 진행자가 사용자에게 묻지 않고 정한 것들이다.
각 항목은 "무엇을 정했나"와 "틀렸다면 드는 비용"만 적었다.
출처는 `.superpowers/sdd/` 아래의 첫 계획 기록(R1~R40)과 게이트 재설계 기록(P1~P40, R-T2a, R-T4, R-T5)이다.
사용자가 직접 정한 것(예: "운영체제로 막기", "지름길 기준으로 마무리")은 여기 넣지 않았다.

## 먼저 봐 주실 것

- **빌드 확인은 게이트를 끄는 파일만 막음** (P38): 설계 기록 폴더, 지문 저장 위치, 설정 파일, 플러그인 폴더만 쓸 수 없고 홈 캐시 등은 쓸 수 있다. 작정한 빌드는 사용자 실행 폴더에 프로그램을 심을 수 있다(범위 밖).
- **Stop은 같은 위반을 한 번만 막음** (P19): 에이전트가 위반을 고치지 않고 넘어가도 두 번째 Stop은 통과한다. 놓친 변경을 알림으로만 알게 될 수 있다.
- **직접 고친 파일도 `GA 상태승인`이 필요** (P12): 사용자가 손으로 고친 설계 파일도 승인 전까지 쓰기가 잠긴다. 잠긴 이유가 낯설 수 있다.
- **열린 가정이 있으면 승인과 새 라운드 불가** (R19): 지난 라운드의 가정까지 모두 풀어야 다음으로 간다. 작업이 막혀 보일 수 있다.
- **프로젝트 루트는 첫 `.git` 폴더에서 멈춤** (R29): 모노레포라면 저장소 루트나 그 아래에서 `ga init`을 해야 한다.

## 설계 기록과 단계

- **승인은 보고서의 단계·라운드를 확인** (R15): 승인하려면 검증 보고서의 단계와 라운드가 현재와 같아야 한다. 틀렸다면: 승인마다 `ga verify`를 한 번 더 돌려야 한다.
- **사용자 명령은 한 번에 처리하고 실패하면 되돌림** (R16): 한 프롬프트의 `GA` 줄을 순서대로 처리하되 하나라도 실패하면 전부 원래대로 돌린다. 틀렸다면: 처리 도중 비정상 종료하면 백업을 손으로 복원해야 한다.
- **입력 단계 통과 조건** (R18): 입력 단계는 중요도 높은 동인 1개 이상과 연속된 반복 번호가 있어야 하고, 반복 단계는 현재 반복의 결정이 1개 이상 있어야 한다. 틀렸다면: 불필요하게 막히는 경우가 늘어난다.
- **열린 가정이 있으면 승인과 새 라운드 불가** (R19): 모든 라운드의 열린 가정과 질문을 세어, 남아 있으면 승인과 `GA 새라운드`를 막는다. 틀렸다면: 지난 항목을 먼저 정리해야 새 라운드를 열 수 있다.
- **편차 결정은 사용자만 확정** (R21): `ga resolve`는 편차 결정 항목을 거부하고, 편차는 `GA 확인 DEC-n`으로만 승인하며, 열린 편차가 있으면 새 라운드도 막는다. 틀렸다면: 없음. (계획 블록은 현재 라운드만 보여 준다.)
- **항목을 고치면 해소가 풀림** (R25): 해소된 항목의 내용을 바꾸면 다시 열리고 이전 해소 기록은 남긴다. 틀렸다면: 사용자가 같은 항목을 다시 확인해야 한다.
- **근거 해소 유지와 문헌 형식** (R27): 증거로 해소한 항목은 해시에 남기고, 문헌 근거는 URL·doi·isbn이어야 하며 검증자가 이를 확인한다. 틀렸다면: ISBN 없는 책은 URL을 달아야 한다.
- **표식이 짝이 안 맞으면 렌더 거부** (R28): 설계 문서의 표식이 불균형이면 렌더를 거부하고 문서 전체를 해시한다. 틀렸다면: 손으로 편집한 문서가 렌더되지 않을 수 있다.
- **프로젝트 루트 탐색** (R29): 루트 탐색은 첫 `.git` 폴더에서 멈추고, `ga init`은 `/`, 홈 폴더, 중첩 루트를 거부한다. 틀렸다면: 모노레포는 저장소 루트 또는 그 아래에서 시작해야 한다.
- **설계 기록이 없으면 `GA` 줄을 막지 않음** (R30): 설계 기록 폴더(`.state`)가 없으면 `GA` 줄을 막지 않고 통과시킨다. 틀렸다면: 없음.
- **경로 정규화** (R2): `ga_canon`은 존재하는 가장 깊은 상위 폴더를 `cd -P`로 정규화하고 나머지를 붙인다. 틀렸다면: 심볼릭 링크 폴더 경로를 잘못 비교한다.
- **사용자 명령 목록 변수** (R4): `usercmd.sh`가 `GA_VERBS`를 정의하고 불러올 때는 함수와 변수만 만든다. 틀렸다면: 12번 작업 테스트가 실패하며 고치기 쉽다.
- **`ga` 실행 경로 출력** (R5): 플러그인 `bin/`이 PATH에 없으면 세션 시작 때 `ga 실행 경로: <절대경로>` 한 줄을 항상 출력한다. 틀렸다면: 세션마다 컨텍스트 한 줄이 늘어난다.
- **MCP 도구 추가** (P2, P9): 상태 격리 설치용 `ga_enforce`와 반박용 `ga_dispute`를 MCP 도구로 추가해 도구가 12개가 된다. 틀렸다면: 도구가 하나 더 늘 뿐이다.
- **MCP 루트는 세션 루트와 같아야 함** (P10): `CLAUDE_PROJECT_DIR`가 있으면 도구의 루트 인자가 그 루트와 달라 오류가 난다. 틀렸다면: 한 세션에서 다른 프로젝트를 다룰 수 없다.
- **`docs` 심볼릭 링크는 `ga init` 거부** (P11): `docs`, `docs/architecture`, `.state` 중 하나가 심볼릭 링크면 `ga init`이 거부한다. 틀렸다면: `docs`를 링크로 쓰는 사용자는 실제 폴더로 바꿔야 한다.

## 승인과 변경 감시 (결과 확인)

- **스냅샷이 없으면 그때 촬영** (P6): 옛 설계처럼 스냅샷이 없으면 지금 상태를 기준으로 찍고 그 사실을 한 번 알린다. 틀렸다면: 첫 검사 이전의 변경은 잡히지 않는다.
- **플러그인 폴더 변경은 늘 위반** (P7): 플러그인 폴더가 프로젝트 안에 있으면 모든 단계에서 그 아래 변경은 위반이다. 틀렸다면: 없음.
- **`GA 재개`와 `GA 상태승인`은 기준을 새로 찍음** (P12): 둘 다 파일 스냅샷을 새로 찍고, 상태승인은 지문도 다시 기록한다. 틀렸다면: 에이전트의 무단 변경을 한 번의 명령으로 받아들일 수 있다(목록은 보여 준다).
- **지문 불일치는 Stop을 한 번만 막음** (P13): 지문 불일치는 Stop을 한 번 막고 이후 알림으로 통과하며, 변경 위반은 계속 막는다. 틀렸다면: 없음.
- **속도 시험은 넉넉한 한도로** (P14): 게이트 평균 300ms, 파일 만 개의 Stop 2초 미만으로 시험한다. 틀렸다면: 그 아래의 느려짐은 알아채지 못한다.
- **지문 기록이 없거나 해시 도구가 없으면 의심으로 취급** (P8): 설계가 진행 중에 이런 경우 승인을 막고 Stop이 알린다. 틀렸다면: 기록을 잃은 프로젝트에서 프롬프트가 하나 늘어난다.
- **지문 불일치 중 상태 쓰기 거절** (P3): 상태를 쓰는 모든 `ga` 명령은 지문이 맞지 않으면 거절하고 사용자 명령은 허용한다. 틀렸다면: 없음.
- **지문은 실제로 쓴 뒤에만 기록** (P4): 읽기 명령은 데이터 폴더를 건드리지 않는다. 틀렸다면: 없음.
- **지문 기록은 조용히 다시 만들지 않음** (P17): 없는 지문 기록은 `ga init`과 `GA 상태승인`만 만들고 다른 경로는 빈 채로 둔다. 틀렸다면: 기록을 잃으면 사용자가 직접 승인해야 한다.
- **Stop은 위반 묶음마다 한 번만 막고 되돌리라 하지 않음** (P19): 같은 위반 묶음은 한 번만 막고, 목록을 사용자에게 보여 되돌릴지 묻거나 `GA 상태승인`을 입력하게 한다. 틀렸다면: 에이전트가 위반을 두고 넘어갈 수 있다(승인은 계속 막힘). (P1의 설정 파일 예외를 대체)
- **OS 메타 파일은 변경이 아님** (P25, M1): `.DS_Store`, `._*`, `Thumbs.db` 등은 변경으로 보지 않는다. 단 `._`로 시작하는 폴더 안의 파일은 변경이다. 틀렸다면: 이 이름의 파일이 바뀌어도 모른다.
- **git은 목록만 만들고 내용 비교는 ga가 함** (P29): git은 `ls-files` 등 목록과 필터 없는 해시에만 쓰고, 크기·수정시각·inode 기록으로 변경을 직접 비교한다. 틀렸다면: 속도가 느려지거나 `결과 확인 불가`가 늘어난다.
- **git 구조가 이상하면 닫힌 채로 실패** (P29): 일반 연결 작업트리가 아니면 `결과 확인 불가`로 막고, git 호출 실패도 위반이다. 틀렸다면: 특이한 저장소에서 승인이 막힌다.
- **`.gitignore` 변경은 항상 보임** (P29): 새로 만들거나 바뀐 `.gitignore`는 스스로를 무시해도 변경으로 잡는다. 틀렸다면: 무시 파일 뒤의 변경을 놓친다.

## 셸 격리와 쓰기 보호

- **방어 대상은 쉬운 우회** (P26, P37, 사용자 지시): 셸이나 쓰기 도구로 기록 지우기·고치기, 설정으로 격리 끄기, 플러그인 고치기, 단계 밖 쓰기, 대신 승인을 막는다. 작정하고 짠 공격은 한계로 적는다. 틀렸다면: 작정한 공격은 막지 못한다.
- **세션 루트는 하네스가 준 값** (P15): 훅은 `CLAUDE_PROJECT_DIR`로 설계를 찾고 작업 폴더를 믿지 않으며, `.state` 경로는 경로만 보고 막는다. 틀렸다면: `cd`로 설계 기록 폴더 보호를 피할 수 있다.
- **평범한 작업 파일은 막지 않음** (P39): `.git/config`, `.git/hooks`, `.mcp.json`, `.claude/hooks`, `~/.claude.json`, 다른 플러그인 폴더는 쓰기 도구로 쓸 수 있다. 틀렸다면: 이 파일로 나중에 격리 밖 실행을 꾸밀 수 있다(작정한 공격, 범위 밖).
- **일시정지는 단계 규칙만 푼다** (P21): `GA 일시정지`는 단계표와 승인만 끄고 설계 기록·지문·설정·플러그인 보호는 유지한다. `GA 재개`는 받아들인 파일 목록(20개까지)을 보여 준다. 틀렸다면: 일시정지 중에도 이 파일을 못 고친다.
- **`excludedCommands`는 경고** (P22): 샌드박스 제외 명령이 있으면 상태에 경고를 넣고 세션 시작과 `systemMessage`로 보여 준다. 틀렸다면: 제외 명령은 격리 없이 돌아간다.
- **`GA 격리해제`** (P23): `enforce.sh uninstall`이 설치 때 더한 것만 지우고, 사용자 전용 `GA 격리해제`로만 부른다. 틀렸다면: 다른 설정이 섞인 경우 일부가 남는다.
- **격리 설정 파일은 Claude Code가 읽는 것을 확인** (P24): 확실하지 않은 저장소 구조(bare 등)는 설치를 거부하고 상태를 비활성으로 보고한다. 틀렸다면: 특이한 저장소는 격리를 쓰지 못한다.
- **사용자의 전역 git 제외 목록을 읽음** (P40): IDE 파일 같은 것이 변경으로 잡혀 종료가 막히지 않게, 전역 제외 목록을 패턴으로만 읽는다. 틀렸다면: 그 목록을 고쳐 파일을 숨길 수 있다(프로젝트 밖, 권한 요청 필요).
- **샌드박스 밖 코드는 시스템 도구만** (P28): 진입점은 PATH를 시스템 폴더로 고정하고 `git`은 개발자 폴더에서 찾으며 도구가 없으면 닫힌 채로 실패한다. 틀렸다면: 특이한 도구 설치 위치에서 도구를 못 찾는다.
- **파일 한 개는 한 가지 표기** (P31): `/System/Volumes/Data` 접두를 떼고 디스크의 대소문자를 써서 경로를 하나로 맞춘다. 틀렸다면: 다른 표기로 보호를 우회한다.
- **훅 판정은 `jq` 없을 때도 보호 유지** (P32): `jq`를 쓸 수 없고 `PAUSED` 표식이 있어도 설계 기록 폴더와 지문 저장소 쓰기는 막는다. 틀렸다면: 없음.
- **지문 오류 중에는 Stop이 장부 형식 오류로 막지 않음** (P32): 지문이 안 맞는 동안 에이전트가 못 고치는 오류로는 막지 않는다. 틀렸다면: 장부 오류 알림이 늦어진다.
- **보호 설명 문구를 사실대로 수정** (P32): `capabilities.json`과 `excludedCommands` 경고의 과장된 문구를 현재 보호 범위에 맞춘다. 틀렸다면: 사용자가 보호를 과신한다.

## 검증 패널과 과금

- **API 과금을 켤 수 있는 설정은 모두 막음** (R12): 설정 `.env`, `CLAUDE_CONFIG_DIR`, 작업 폴더와 상위의 `.claude/settings*.json`을 검사한다. 틀렸다면: 관계없는 env 항목에도 거부가 나올 수 있다.
- **과금 방어 강화** (R13): `--bare=`, 금지 플래그를 담은 실행, 기록이 있어도 api_key 등을 거부하는 하한, 환경 변수 이름 검증을 넣는다. 틀렸다면: 없음.
- **러너 안에서는 훅을 끄고 도구를 제한** (R24, R26): `GA_IN_RUNNER`일 때 사용자 명령 등은 아무것도 하지 않고, 러너는 훅 비활성·엄격한 MCP·읽기 전용 도구로 돈다. 틀렸다면: 없음.
- **러너별 사전 점검과 일반화** (R33): 사전 점검 스크립트, 과금 점검, 컨텍스트를 러너별로 두고 README를 둔다. 틀렸다면: 다시 정리할 위험이 있다(테스트는 유지).
- **테스트 전용 설정 제한** (R34): `GA_RUNNERS_DIR`은 `GA_TEST_MODE`일 때만 쓰고, 보고서에 러너 경로를 적는다. 틀렸다면: 없음.
- **러너 명령은 프로젝트 밖의 절대 경로에서만 찾음** (P16): 상대 경로나 프로젝트 안 경로는 건너뛰고, 실제로 쓴 러너 경로를 보고서에 적는다. 틀렸다면: 프로젝트 안에 둔 러너는 인식되지 않는다.
