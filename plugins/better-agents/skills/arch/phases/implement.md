# `implement` 단계

프로젝트 파일을 쓸 수 있다(SKILL.md 0절의 보호는 그대로). 설계 문서와 대응표대로 세부 로직을 구현한다.

- 대응표에 없는 새 요소나 위치는 쓰기 전에 `ga_add`(kind `mapping`)로 기록한다.
- **설계에서 벗어날 때:** 그 코드를 쓰기 전에 결정을 `"deviation": true`와 함께 `ga_add`로 기록한다(근거, 버린 대안, 드라이버 포함. SKILL.md 3절 "항목 형식"). architecture.md를 고치고 `ga_render`를 부른다. 사용자가 확인하기 전까지 문서에 "미승인 이탈"로 보이니, 내용과 이유를 보여 주고 `GA 확인 DEC-n`을 요청한다. 이탈 승인은 이것으로만 기록된다(이탈 결정에 `ga_resolve`는 거부된다).
- **새 기능이 들어오면:** 미승인 이탈과 해결되지 않은 가정·질문을 모두 먼저 해결한 뒤 `GA 새라운드`를 요청한다(남아 있으면 거부된다). 같은 architecture.md에서 라운드 번호가 1 올라 `inputs`부터 다시 시작한다. 새 라운드는 자기 `purpose` 드라이버와 1부터 번호를 매긴 자기 `high` 드라이버가 필요하다. 이전 라운드의 드라이버, 결정, 대응표는 승인 조건에 세지 않는다.
