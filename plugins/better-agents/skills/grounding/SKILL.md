# 판단의 근거 등급

모든 판단에는 근거가 있어야 한다. 근거의 강도에 따라 판단을 세 등급으로 나누고, 등급마다 처리가 정해져 있다.

## 1. 세 등급

| 등급 | 조건 | 처리 |
|---|---|---|
| 확정 | 직접 근거가 있다 | 완료 |
| 근거 있는 가정 | 직접 근거는 없고 간접 근거가 있다 | **미완료.** 사용자 확인이나 추가 조사로 직접 근거를 얻어야 완료된다 |
| 근거 없는 가정 | 근거가 없다 | **금지.** 대신 질문한다. 질문에도 탐색 기록을 붙인다 |

## 2. 직접 근거로 인정하는 것

1. 사용자가 말한 요구사항이나 결정
2. 대상 코드나 환경에서 확인한 사실 (`파일:줄`, 명령 출력)
3. 검증된 문헌이나 방법론 (출처 URL 또는 서지)
4. 측정이나 실험 결과

## 3. 간접 근거로 인정하는 것

- 기존 코드의 관례
- 프레임워크 기본값
- 문헌상 일반적인 경우
- 사용자가 밝힌 목표에서 이끌어 낸 추론

## 4. 기록 형식

| 대상 | 칸 |
|---|---|
| 결정 | 선택 \| 근거 (등급과 출처) \| 버린 대안과 버린 이유 |
| 가정 | 가정 내용 \| 간접 근거 \| 직접 근거 탐색 기록 \| 다른 가능한 가정과 버린 이유 |
| 질문 | 질문 \| 탐색 기록 \| 답에 따라 무엇이 바뀌는가 |

- 가정에는 간접 근거, 직접 근거 탐색 기록, 다른 가능한 가정과 버린 이유가 모두 있어야 한다. "다른 가능한 가정" 칸은 이상한 가정을 거르기 위한 것이다.
- 사용자 제약 때문에 강제된 결정은 버린 대안 칸에 `대안 없음: 사용자 제약 (출처)`라고 쓸 수 있다. 출처는 반드시 사용자 발언이어야 한다.

**원장에 올리는 것**
- 아키텍처상 의미 있는 결정, 모든 가정, 모든 질문

**원장에 올리지 않는 것**
- 그 밖의 판단. 대신 응답 안에서 근거를 표시한다.

## 5. 탐색 범위

탐색 기록에는 최소한 아래 범위를 본 결과가 들어가야 한다. 해당하지 않는 곳은 "해당 없음"과 그 이유를 적는다.

- 대상 프로젝트의 코드
- 프로젝트 문서: README, CLAUDE.md, `docs/`, 메모리 디렉터리
- 현재 대화
- 웹이나 문헌 (일반 지식에 관한 판단일 때)

## 6. 미래 기능에도 같은 등급을 적용한다

- 사용자가 밝힌 로드맵에 있는 기능: **확정**
- 도메인 문헌상 흔한 확장: **근거 있는 가정** (확인을 받아야 한다)
- 근거가 없는 기능: 설계에 **반영하지 않는다**

## 7. 적용 범위

- 아키텍처 스킬 안에서는 게이트로 강제한다.
- 그 밖의 모든 작업에서는 요청마다 이 규칙 문장이 주입되며, 강제되지는 않는다.

응답에서 판단마다 근거 종류를 표시한다.
