# 설명 양식

사용자는 내 작업 과정을 보지 못한다. 그래서 정해 달라고 할 때는 한 번 읽고 무엇이 됐는지, 무엇을 고를지, 고르면 무슨 일이 생기는지 알 수 있어야 한다. 그 밖의 글까지 양식으로 쓰면 무겁고 길어진다.

## 1. 글의 종류

- **결정 요청**(사용자에게 승인이나 방향 선택을 받으려는 질문): 이때만 2절 양식을 그대로 쓴다. 답변, 앱의 요약 칸, 질문 창, 버튼에 모두 쓴다.
- **그 밖의 글**(진행 상황, 정할 일 없는 결과, 사실 하나나 예/아니오 질문의 답): 양식 없이 짧게 쓴다. 제목과 `무엇`/`예`/`영향` 항목을 쓰지 않는다. 짧은 답은 1~3문장이다.
- 둘 다 4절의 말투와 낱말을 지킨다.

## 2. 보고 양식

```
## 지금 상황
<무엇이 어떻게 됐는지 1문장>. <사용자가 정할 일과 내 추천 1~2문장, 또는 "정하실 것은 없습니다.">

**<종류> 1: <요점을 담은 짧은 문장>**
- 무엇: <한 문장>
- 예: <사용자가 실제로 칠 명령이나 볼 장면, 그리고 그 결과 한 문장>
- 영향: <사용자에게 생기는 일 한 문장>

**<종류> 2: <요점을 담은 짧은 문장>**
- 무엇: …
- 예: …
- 영향: …

그 밖에 작은 것 <n>개가 있습니다. 원하시면 설명드리겠습니다.

## 정해 주실 것
- **<선택지 이름> (추천)**: 고르면 <일어나는 일>. 이유: <한 문장>.
- **<선택지 이름>**: 고르면 <일어나는 일>.

<질문 한 문장>
```

## 3. 양식의 각 부분

- 항목 제목의 종류는 사용자가 바로 알아보는 말이다("새 버그", "고친 것", "남은 것", "확인한 것"). 요점 문장은 주제가 아니라 결론이다("고친 결과"가 아니라 "평범한 명령이 다시 통과합니다").
- 항목 본문은 언제나 `- 무엇:`, `- 예:`, `- 영향:` 세 줄이고 줄마다 한 문장이다. 하위 목록은 만들지 않는다.
- 항목은 한 보고에 3개까지다. 나머지는 "그 밖에 작은 것 n개" 한 줄로 줄인다.
- 확인한 방법이 있으면 항목 다음에 한 문장으로 쓴다("두 버그 모두 직접 재현해서 확인했습니다.").
- `## 정해 주실 것`은 정할 일이 있을 때만 쓴다.
- 마지막 줄 질문은 앞을 읽지 않아도 무엇을 고르는지 알 수 있게 쓴다.
- 앱이 요약 칸이나 질문 창을 따로 보여 주면 요약은 `## 지금 상황`과 같은 낱말로, 질문은 마지막 줄과 같은 뜻으로 쓰고, 버튼은 선택지 이름을 그대로 쓴다.

## 4. 말투와 낱말

- 한국어로 쓴다. 코드, 명령, 파일 경로만 원래 글자 그대로 백틱 안에 쓴다.
- 대상은 뜻이 드러나는 한국어 이름으로 부르고("N1" 대신 "평범한 명령까지 막는 버그"), 한 번 정한 이름은 끝까지 같게 쓴다.
- 전문용어는 쉬운 말로 바꾼다("fail-open" 대신 "오류가 나면 막지 않고 통과시킴", "글롭" 대신 "`*` 같은 와일드카드"). 바꿀 수 없는 용어는 처음 나올 때 괄호로 뜻을 붙인다.
- 한 문장에는 생각 하나만 담는다. "이것", "그것" 대신 가리키는 대상을 쓴다.

## 5. 보내기 전 점검

1. 결정 요청이 아닌데 양식을 썼으면 양식 없이 짧게 고친다. 결정 요청이면 `## 지금 상황`이 맨 앞에 3문장 이내로 있는가?
2. 모든 항목이 제목 한 줄과 `무엇`, `예`, `영향` 세 줄인가?
3. 사용자가 쓴 적 없고 내가 풀어 쓰지도 않은 번호, 줄임말, 영어 용어가 남았으면 바꾼다.
4. 정할 일이 있으면 마지막 줄이 질문인가?
5. 이 대화를 처음 보는 개발자가 한 번 읽고 이해하는가?

## 지금 상황
플러그인 수정 중에 새 버그 2개가 생겼습니다. 써 보기 전에 먼저 고칠지 정해 주세요. 저는 먼저 고치기를 추천합니다.

**새 버그 1: 평범한 명령까지 막습니다**
- 무엇: 설계 기록 폴더(`docs/architecture/.state`)를 지키는 규칙이 상관없는 파일 삭제까지 막습니다.

- 영향: 코드를 짜는 단계에서 에이전트가 자주 멈춥니다.

**새 버그 2: 다른 저장소 폴더 안에서는 보호가 꺼집니다**
- 무엇: 프로젝트 안의 별도 git 저장소 폴더에서는 플러그인이 설계 중인 프로젝트를 찾지 못합니다.
- 예: `vendor/lib`에서 `rm -rf ../../docs/architecture/.state`를 실행하면 막히지 않고 설계 기록이 지워집니다.
- 영향: 지켜야 할 설계 기록을 잃을 수 있습니다.

두 버그 모두 직접 재현해서 확인했습니다.

## 정해 주실 것
- **먼저 고치기 (추천)**: 고르면 두 버그를 고치고 다시 검사한 뒤 써 봅니다. 이유: 버그 1이 남으면 계속 막혀 평가할 수 없습니다.
- **바로 써 보기**: 고르면 지금 상태로 써 봅니다. 자주 막힐 수 있습니다.

새 버그 2개를 먼저 고칠까요, 지금 상태로 바로 써 볼까요?
